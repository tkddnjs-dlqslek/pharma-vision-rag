## 2. 멀티홉(D유형) 실패 사례

D문항은 두 가지 구조로 나뉨. D01, D02, D04, D05, D09는 **단일 회사(Sanofi), 여러 분기/연도**가 홉이고,
D06, D07, D08, D10은 **여러 회사, 같은 시점**이 홉임. 실패 양상이 서로 다름.

### 2.1 단일 회사, 다중 분기(D01, D02, D04, D05, D09)

## 4. 표 문항에서 리랭커의 R@1 하락

손실 14건을 리랭커가 무엇을 대신 택했는지로 나누면 두 유형임.

- **연도/분기 쌍둥이 표로 이동**: B07(20-F FY2025 p80 -> FY2024 p89), B12(2024Q4 p1 -> 2024Q1 p1),

- **같은 문서 안 다른 지표 표로 이동**: B16(Novartis Q2 덱 순매출 p20 -> 순부채 p37),

  지표를 동시에 틀림)

반대로 회복 8건은 리랭커가 dense가 놓친 **정확한 부록 표(appendix table)** 를 서술형 페이지나 엉뚱한

슬라이드 -> Total Revenue 표).

**해석**: bge-reranker-v2-m3는 "이게 재무 표 구조로 보이는가"에는 민감하지만, 질문에 박힌 연도/분기
토큰(2024 대 2025, Q1 대 Q4)이나 지표명(순매출 대 순부채)의 정합성은 dense 임베딩보다 오히려 약하게
반영하는 것으로 보임. 표 문항 R@1이 떨어진 근본 원인은 "표를 못 찾아서"가 아니라 "표는 찾는데 엉뚱한
연도나 엉뚱한 지표의 표를 고름"임.

## 5. 하이브리드 융합 효과

vision R@1과 hybrid/hybrid_rerank R@1을 문항 단위로 비교.

| 비교 | 융합이 손해 본 건수 | 융합이 도움 된 건수 |
|---|---|---|
| vision 대 hybrid_rerank | 17 | 10 |
| vision 대 hybrid(리랭크 없음) | 28 | (역방향은 별도 집계 안 함, 표 기준 R@1 0.40 대 0.56로 이미 손해가 더 큼) |

hybrid_rerank가 vision을 이긴 10건은 정확히 1절, 4절에서 이미 확인한 표/본문 실패들과 겹침: B07, B13,
B20, C05, C06. 즉 텍스트 쪽 경로가 비전이 놓친 "같은 문서 다른 페이지" 혼동을 구제하는 역할을 함.

반대로 융합이 손해를 보는 17건은 대부분 vision이 정확히 찾은 차트 페이지를, RRF가 순위를 밀어내고
텍스트 쪽이 선호하는 다른 페이지로 대체하는 경우임. 예: A04(vision이 `sanofi_2025Q2_deck.pdf:9`를
정확히 찾았으나 hybrid_rerank는 `sanofi_2025Q2_pr.pdf:2`로 대체, A04는 `visual_only=true` 문항이라
텍스트 레이어에 답이 아예 없는데도 텍스트 쪽 점수가 순위를 끌어올림), B16, B17(4절과 동일한 지표
혼동이 융합에도 그대로 전파됨).

**결론**: 고정 가중치 RRF는 비전이 이미 잘 맞히는 차트/시각 전용 문항에서 텍스트 쪽의 false positive를
끌어들여 순위를 훼손하는 경우가, 비전의 실수를 구제하는 경우보다 많음(17 대 10, 리랭크 없는 hybrid는
28건으로 더 나쁨). `EXPERIMENT_PLAN.md`가 보고한 R@1 0.56(vision) 대 0.51(hybrid_rerank) 대
0.40(hybrid)의 순서와 정확히 일치.

## 6. Agentic 모드(E4)에 대한 시사점

계획서 3.3절의 도구(`list_documents`, `search_text` 문서 필터, `search_pages`, `open_page`, `calculate`)
기준으로 위 실패 유형을 분류.

| 실패 유형 | 근거 절 | 문서 필터로 해결 | 질의 분해 필요 | 새 도구 불필요(현재 파이프라인 한계) |
|---|---|---|---|---|
| 쌍둥이 페이지(연도/분기, 같은 레이아웃) | 1.2, 2.1, 4 | **예**. 질문이 명시한 연도/분기로 `list_documents` 후 `search_text`를 그 문서로만 제한하면 A03(ko), A13(ko), B12, 4절의 손실 14건 대부분이 원천 차단됨 | 아니오 | |
| 다중 회사 top5 독점(D06~D08, D10) | 2.2 | 예(홉별 필터) | **예**. 회사별로 질문을 쪼개 각각 `search_text`/`search_pages`를 실행해야 함(단일 검색으로는 구조적으로 불가능, R@5 0.28~0.42가 상한) | |
| 단일 회사 다중 분기 멀티홉(D01,D02,D04,D05,D09) | 2.1 | 예(분기별 필터) | **예**. `calculate`도 필요(D01, D02는 차이/추정값을 구해야 함) | |
| 같은 문서, 다른 페이지(B07,B13,B14,B15,B17,C03,C06 등) | 1.2, 4 | 아니오(이미 올바른 문서임) | 아니오 | **예**. `search_pages`가 문서 내부에서 지표명이나 페이지 유형까지 구분해 찾아야 하고, `open_page`로 후보를 열어 `answer_keys`류 수치가 실제로 있는지 확인하는 검증 스텝이 있어야 함(현재 파이프라인은 검증 없이 최상위 순위를 그대로 반환) |
| 한국어/영어 격차 | 3 | 아니오 | 아니오 | **예**(목록에 없는 기능). 질문을 영어로 재작성(query rewrite)하거나 한/영 병렬 검색 후 병합하는 절차가 필요한데 현재 5개 도구 목록에는 없음. E4 설계 시 추가 검토 필요 |
| 골드 격차(A02, A03, A05, 부분 정답 B02/B03/B07) | 1.3, 1.4 | 해당 없음(평가셋 문제) | 해당 없음 | 에이전트 이전에 **평가셋 정합성**부터 수정 필요. 골드 누락 상태로 E4를 벤치마크하면 실제로는 맞힌 답을 오답 처리하게 됨 |

요약하면, 실패의 절반 가까이(쌍둥이 페이지, 다중 회사/다중 분기 독점)는 문서 필터와 질의 분해만으로
구조적으로 해결 가능함. 반면 "같은 문서 안에서 엉뚱한 페이지/표를 고르는" 유형(4절의 리랭커 손실,
1.2절의 "같은 문서 다른 페이지" 14건)은 필터로 막히지 않고, `open_page` 검증 스텝처럼 계획서에 이미
있는 도구를 더 적극적으로 쓰는 수밖에 없음. 한국어/영어 격차는 현재 5개 도구로는 못 고치는 유일한
유형으로 확인됨.

### 7.3 후속 조치 제안

- **평가셋 감사 우선**: 7.1의 확신도 "높음" 3건(A02, A03, A05)은 골드에 반영한 뒤 vision/hybrid 벤치마크를
  재계산해야 실제 R@1, R@5 수치가 정확해짐. 현재 수치는 실제보다 비전에 불리하게 나와 있을 가능성이 있음.
- **표 문항 리랭커 재검토**: 4절에서 확인한 "연도 쌍둥이 표"와 "같은 문서 다른 지표 표" 혼동은 리랭커
  입력에 문서 메타데이터(연도, 분기, 지표명)를 주입하거나, 질문에서 추출한 기간을 사후 필터로 강제하는
  방식으로 완화 가능. 현재 리랭커는 순수 텍스트만 비교함.
- **RRF 가중치 재검토**: 5절에서 확인했듯 고정 가중치 RRF는 비전 단독보다 못함. `visual_only=true`
  문항(A04, A08 등)에서는 텍스트 쪽 점수를 아예 배제하거나 크게 낮추는 조건부 가중치가 필요.
- **E4 설계 우선순위**: 6절 표 기준, 문서 필터와 질의 분해를 먼저 구현하면 D유형과 쌍둥이 페이지 실패의
  상당수가 해소됨. `open_page` 검증 스텝(후보 페이지를 열어 답이 실제로 있는지 확인)은 "같은 문서 다른
  페이지" 유형에 필수이므로 설계에서 생략하지 말 것. 한국어/영어 격차는 현재 도구 목록 밖의 문제로 별도
  검토 필요(질의 재작성 또는 병렬 한/영 검색).
